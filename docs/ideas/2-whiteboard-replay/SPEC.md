# 白板讲解回放 · Spec 草案

状态：待产品审阅。用于讨论首版和指导后续拆票。

## 使用场景与目标

缺席评审的研发看录屏时，想暂停并沿另一条分支查看条件。切回原图重新定位时，可能认错分支，或无法把讲解中的理由对应到正确路径。首版帮助他在评审当天的图上独立找对分支，并讲清当时选择该路径的理由。仅缩短定位耗时不足以支持投入。

## 一段讲解如何产生、分享和观看

1. 评审现场先把图改定。讲解者主动开始录制关键片段，对着该版图指出关键分支，说明当时选择它的理由，并结束录制。首版使用定稿，省去改图过程的回放和会后补录。
2. 缺席研发收到试用链接，点开即可观看。播放时，讲解声音、指示位置和讲解者视野要能对应到录制时的那版图。即使原图后来改动，片段仍展示当时的分支。
3. 研发暂停时，讲解进度停止。他可以从当前位置平移、缩放，顺着图查看另一条分支的条件。
4. 继续播放时，回到讲解者在暂停时刻的视野，从该时刻接着听。作者说“这里”时，研发能看出指的是哪个节点。

## 功能验收示例

| 操作 | 预期 |
|---|---|
| 录制定稿上的分支 A，结束后修改原图，再从试用链接打开讲解 | 看到录制时的 A，听到与它对应的讲解 |
| 在 A 暂停，平移并放大相邻分支 B | 可以查看 B，讲解进度停在暂停处 |
| 从 B 点击继续播放 | 时间从暂停处继续，视野回到讲解者当时所看的 A |

## 产品验收与停止条件

用同一次讲解、同版原图和同一道题比较「录屏＋原图」与白板回放。给缺席评审的研发一笔新订单，让他在没有产品经理提示的情况下选出分支，并用自己的话解释会上讨论过的选择理由。分支与理由都正确才算完成。会上未讨论过的理由不作失败项。

若录屏加原图已足以让研发独立正确完成任务，无需回来追问产品，就停止投入。仅节省定位时间不足以立项。本轮确认的是验收口径，试用结果待实际验证。

## 待审范围

“点链接即可看”已确认。链接能否转发给其他人、暂停时可浏览的画布范围，以及最小试用原型的具体形式仍待决定。
