## 用户信号与未知点

[#9482](https://github.com/excalidraw/excalidraw/issues/9482) 请求同步回放声音、激光笔或选中动作。维护者表示愿意讨论用途和 UX。[#9363](https://github.com/excalidraw/excalidraw/issues/9363) 的反馈者将白板嵌入自己的平台，希望记录交互和状态。两者都提到回放，但第二条面向集成开发者。现有反馈尚未验证讲解对象、分享频率或相对普通录屏的价值。

演练候选场景：产品经理录一段流程图讲解，另一位同事稍后独立观看。成功的观察方式是让同事指出作者解释的分支并复述理由。先用已有录屏给目标读者看同一段内容，观察他们是否需要暂停后放大图、定位元素或进入白板继续工作。

## 三种做法

| 方案 | 收件人能做什么 | 可行性和成本 |
|---|---|---|
| 普通演示视频 | 直接播放作者当时看到的画面 | 可先用现成录屏验证需求。大图放大后的清晰度受录制分辨率影响。 |
| 画布快照、声音和指示轨迹 | 回到讲解当时的版本，按声音进度重放指示；可设计成暂停后自由查看图 | 推荐探索。需要一并保存图片资源、确定场景坐标及视口变换、控制包体。 |
| 在最新白板上回放 | 看最新内容，并尝试定位原元素 | 需要定义元素移动、删除和版本冲突时的行为。自由指示的位置也未必绑定元素。 |

## 代码检查

- packages/excalidraw/laserTrails.ts 的 addPointToPath 接收轨迹点，适合作为采样候选。应记录笔划起止，避免跨笔划连线。
- packages/excalidraw/types.ts 暴露 onPointerUpdate、onChange 和 selectedElementIds。可从这里研究指针、场景和选中状态，实际调用频率及坐标系还需在应用内验证。
- excalidraw-app/data/index.ts 的 exportToBackend 负责加密场景、上传资源、生成链接。它提供现有分享入口；把录音加入链接需要验证载荷格式、限额、接收端兼容性。

## 浏览器实验

使用本目录 probe.mjs、Node 22 和一次性 Chrome 调试实例（loopback、允许自动播放）。启动 Chrome 后执行 node probe.mjs http://127.0.0.1:9229 。页面 A 用 Web Audio 合成音和 MediaRecorder 生成录音，记下两个合成指示点。把序列化的数据传入新页面 B，按 audio.currentTime 派发两个点。脚本检查音频非空及事件顺序。原始实测数据见 result.json。依据：[W3C MediaStream Recording](https://www.w3.org/TR/mediastream-recording/)。

本实验验证媒体和事件数据能跨页面重新播放。尚未接入 Excalidraw 画布，未验证麦克风授权、真实设备听感、快照渲染、拖动进度、长录音漂移、跨设备文件传输或在线分享。

## 产品讨论

建议第一轮演示固定一幅含两个分支的画布。作者录音并用激光笔分别指向两个分支，接收者打开讲解看回放。建议先验证一个可传递的文件；如果用户的核心目标是点链接即看，应改为优先验证线上分享。若接受快照，后续还要决定是否录制画布编辑、平移和缩放。产品确认使用场景和交付体验后再写 Spec。
